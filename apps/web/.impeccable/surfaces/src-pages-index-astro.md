# Landing (`/`)

## Scope

The entry page of the open-source project. Visitor mode: **Persuade**. It shares the theme of the editor (`src/styles/global.css`).

## Audience and action

Backend and full-stack developers deciding whether to try Design DB. The one action: **Abrir el editor** (`/app`). Secondary: the repository on GitHub (https://github.com/Freddyz5/design-db).

## Proof

A live demonstration with the project's own core: the visitor types SQL and the board updates. No screenshots, no invented users, numbers or testimonials. Claims allowed: open source, local, no account (the pilot keeps everything in the browser), SQL / DBML / Drizzle in both directions.

## Direction contract

THESIS: The first viewport is the product working: a live plan of the visitor's schema, drawn as they type SQL. It refuses the category default of a headline over a screenshot and a row of feature cards.

OWN-WORLD: The editor's blueprint world (see `src-pages-app-astro.md`): petroleum ink on paper with a cyan grid, cyan-tinted dark sheet at night, tables as technical sheets, a title block, IBM Plex Sans Condensed caps for titles, IBM Plex Mono for code, orange only for the primary action and the cursor.

STORY: The visitor types a table, sees it drawn on the plan, sees the same schema as DBML and Drizzle, and opens the editor.

FIRST VIEWPORT: To be designed in DDB-69 (landing de plano), keeping the live demo as the proof. The split-flap board of the previous direction is retired.

FORM: blueprint, shared with the editor (user's direction, 2026-11-14).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
